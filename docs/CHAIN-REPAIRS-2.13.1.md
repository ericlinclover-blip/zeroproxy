# v2.13.1 · 链式代理修复与交互改进

## 修复内容

1. **证书身份分离**：远端 QUIC pin 只用于该远端 TLS 身份校验，不再与本机落地证书比较。`pin_ok` 表示保存了有效格式的远端指纹，不代表已完成远端握手。保留 `pin_mismatch` 字段以兼容旧界面，当前固定为 false；同名诊断 id 改为检查本机证书的可读性。
2. **探测配置同源**：Reality 远端探测使用正式链式出站生成器；不再将合法的空 flow 替换成 Vision。本机入口预热是另一条调用路径，仍按本机主力 Reality 入站要求保留 Vision，链式入站使用空 flow。
3. **并发提交校验**：锁外探测完成后重新检查目标重复、配置端口预留和 OS 监听。入站与 QUIC SOCKS 共用端口预留集合，自动分配冲突时重选；用户显式指定的端口冲突返回 409，不静默替换。
4. **验证绑定配置**：新增探测参数摘要与链式路由版本。切换内层、启停、带宽调整后旧成功失效；配置变化期间返回的探测结果丢弃并返回 409；主力节点测速也不再沿用其它链式路由版本的结果。升级前没有参数摘要的历史结果会显示待验证。
5. **严格出口地址解析**：完整回显正文必须能被 `ipaddress.ip_address` 解析，支持压缩 IPv6；非法地址和包含地址的错误文本不再构成验证成功。配对目标的 IPv4 也使用严格解析。
6. **统一状态显示**：链式卡片、节点列表和连接画布共用健康语义：停用、入口服务未就绪、证书固定待修复、QUIC 内层未就绪、待验证、过期与出口验证结果分别显示。只有近期且匹配配置的有效证据才点亮验证路径。默认出口没有有效结果时显示待验证，不拿备用路线或本机公网地址冒充它的出口。

## 原地更新配对码

新增 `POST /api/chain/entries/{id}/pair`，参数为 `{"code":"ZPC1~…"}`。前端在每条链旁提供“更新配对码”，需要补齐证书固定时显示“重新配对”。

- 先解析并验证新连接，失败时不改原条目；保留现有内层传输，不静默切换到其它协议。
- 更新时保留节点 id、名称、本机入站端口、启停状态、默认出口设置和创建时间。
- 验证期间配置变化或目标被其它条目占用时拒绝提交。
- 应用失败或抛异常时尝试恢复原凭据并重新应用；同步与后台任务均覆盖。原任务继续显示失败，并附恢复结果，不将恢复成功说成更新成功。
- 如果失败期间条目已被其它操作修改，或原目标已被其它条目使用，则不覆盖并发更改，并明确提示核对实际状态。服务恢复失败也会明确报告。
- 无需为了复制现有码而轮换远端共享凭据；轮换仍影响使用该凭据的其它入口。更新窗口关闭后清除输入框中的配对码。

更新前后管理端口与普通订阅令牌保持兼容，无新增运行依赖，无状态文件迁移。旧探测记录保留，但需重新验证才能作为当前健康证据。

## 功能边界

- 默认出口覆盖四类 Xray 入站，不自动接管 Hysteria 2 主节点或 WireGuard。
- 探测验证入口服务器至远端出口，不代表设备至入口的完整实际链路，也不是吞吐量测试。
- 本轮没有增加自动备用出口切换或自动直连回退。
- 代码中的 QUIC 性能文案已改为要求按线路实测，不承诺跨洋必然更快。
