# v2.17.1：AI 登录与网络防泄漏改进

日期：2026-11-20。面板 2.17.1，路由器客户端 1.4.63，zpcore 保持 1.4.0。

## 分析结论

用户报告路由器、电脑和手机均有 AI 网站不流畅、Gemini 经常无法登录的问题。本次确认的是源代码与生成配置中的缺口，未取得失败登录时的网络日志，不能把所有登录失败归因于同一个原因。

| 路径 | 原行为与影响 | 本次改进 |
| --- | --- | --- |
| Gemini 登录 | gemini.google.com 属于 AI 规则，Google 账号/OAuth/验证码/部分静态资源没有同样的显式路由，可能走通用选择或国内规则 | 补充精确的服务域名；覆盖 Clash、sing-box、Android 及引用共用域名表的性能模式 |
| AI 与验证码出口 | AI 和落地组各自测速或手选，可以选出不同出口；延迟变化也可能切换出口 | AI 组只引用落地组；多条内联链路的落地组使用 fallback 而非 url-test，只因健康状态切换 |
| 路由器 DNS | 默认 nameserver 为国内 UDP 53；fake-IP 的 A 查询不会访问它，但其他记录及真实解析可能访问，不能据 fake-IP 推断没有 DNS 披露 | 非 direct 模板默认使用代理 DoH；AI、验证码与检测域名的 DoH 指定各自对应出口，保留节点引导/国内直连解析 |
| 桌面 Clash | 原订阅未定义 DNS，取决于宿主客户端的设置 | 增加仅监听回环的 DNS 配置，不自动授权或开启 TUN |
| Android DNS | 默认代理 DNS 走节点选择组，AI 业务可能走落地组；国内规则排在前面 | AI/验证码 DNS 优先匹配，并经同一对应策略组查询 |
| fake-IP 转发 | TPROXY/REDIRECT 将 198.18.0.0/16 放入私网豁免，应用连接 fake-IP 时可能不进代理 | 从防火墙的直连豁免中移除 fake-IP 网段 |
| TPROXY 路由 | nft 打标后缺少将包送回本机的策略路由；公网特定端口被无条件放行；原规则不限 LAN 接口 | 补齐双栈 local 路由及 fwmark 规则，捕获标记 0x1fe 与代理出站标记 0x1ff 分离；只接管 LAN，不按公网端口豁免 |
| dnsmasq | 私网目的 DNS 在原链中放行，dnsmasq 随后的公网查询未接管 | 保留 DHCP/局域网本地解析，接管本机外发公网 TCP/UDP 53；代理自己的标记查询豁免以避免递归 |
| IPv6 降级 | TPROXY 不支持 IPv6 时只能报告未接管，公网 IPv6 仍可直出 | 在 IPv6 TPROXY 不可用、inet 过滤可用时拒绝 LAN 公网 IPv6 转发，保留 ULA/链路本地/组播；direct 模板例外 |
| 旧固件公网 UDP | REDIRECT 只处理 TCP，QUIC/STUN 可绕过代理 | 活跃 REDIRECT 模式拒绝公网 UDP，保留局域网 UDP；direct 模板例外 |
| 规则失败与停止 | 若干安装错误被忽略，清理循环无界 | 路由/防火墙安装失败返回失败并撤回本轮规则；清理循环有界；停止、切换、revert、卸载均清理专属路由 |

## 使用与升级

先升级面板至 2.17.1，再使用设备页更新命令升级路由器至 1.4.63。只升级面板不会替换路由器的防火墙脚本。电脑与手机更新完整订阅后，检查落地节点的选择；原来 AI 与验证码分别手选的配置将共用落地选择。

电脑 Clash/mihomo 建议启用宿主客户端的 TUN。系统代理只覆盖遵循代理设置的应用，不能保证浏览器外或 UDP/IPv6 的系统流量接管。Android 使用设备页专用 sing-box 1.14+ TUN/VPN 配置；系统要求的 VPN 授权需在手机完成。v2rayNG、Shadowrocket 的 Base64/单节点订阅不能携带本次完整的 DNS 和路由策略，需在对应客户端配置全局 VPN、远程 DNS 与 IPv6 接管。

旧路由器如果只能使用 REDIRECT，公网 UDP 拒绝可能影响游戏、语音和依赖 UDP 的应用。应优先升级至能运行 TUN/TPROXY 的固件；不要将“UDP 被拒绝”解释为“UDP 已代理”。没有 ip6tables、没有 inet 过滤能力的固件仍不能据此保证 IPv6 不直出，必须处理设备或网络的 IPv6 设置。

## 仍然存在的边界

- 本次不是断网锁：主动停止代理会恢复普通上网，TUN 崩溃/重启窗口仍可能恢复系统路由；fw4 reload、流量卸载和多 LAN 接口需要真机验收。
- TPROXY/REDIRECT 只接管安装时识别的 LAN 接口，多 VLAN/访客网络需要分别配置。没有 IPv6 内核支持时不能凭 DNS 的 ipv6=false 宣称 IPv6 已被系统禁用。
- 规则级自定义直连、direct 模板及用户主动选择 DIRECT 保留；REDIRECT 的公网 UDP 保护在防火墙执行，域名直连规则不能豁免它。没有节点时原订阅的直连降级机制没有改为强制断网。规则不是账号风控绕过，也不会改变服务器 IP 的 ASN、共享使用情况或历史信誉。
- 落地 fallback 保留可用性优先：入口不可用/恢复时仍可能切换。多面板骨架仍保留原有的 provider 选择与通用自动组；选择同一落地组不等于所有连接在切换瞬间绝对共用一个公网地址。不同域名的并行连接和 STUN 的通用出口也需抓包核对。
- 国内/节点引导 DNS 仍可直连；这是分流配置，不能将它描述成所有 DNS 均不可见。设备自设 DoH/DoT、不遵循系统代理的程序、浏览器扩展和账号状态需要另行核对。
- 目前尚未在用户真实账号上验证 Gemini 登录。Google 官方也将地区、年龄、账号类型与管理员设置列为访问条件；网络修复不能消除这些限制。
