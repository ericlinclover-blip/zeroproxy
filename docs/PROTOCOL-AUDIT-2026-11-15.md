# 五协议兼容性与稳定性审计（2026-11-15）

结论：当前实现不能称为“每种协议都已最优”。已确认两个 REALITY 节点存在客户端订阅兼容性缺陷，并已完成本地修复；其他协议可用，但本轮短样本无法证明其长期稳定或达到峰值带宽。不能通过随意增加缓冲、关闭证书验证或更换伪装目标解决所有问题。

## 1. 已证实的 REALITY 故障

现场版本：路由器 GL-MT3000 / OpenWrt 24.10.4，mihomo v1.19.32（Go 1.26.8）；服务器 Xray 26.11.9 / 676eaf6（Go 1.27.3），Hysteria 2.13.0。

- 路由器正式实例对两个测试地址各探测三轮，TCP REALITY 与 XHTTP REALITY 均失败；日志有 `REALITY authentication failed`。
- 同期服务器使用自身 Xray 客户端的出网自检通过。因此“服务端自检通过”不足以证明路由器跨内核兼容。
- mihomo v1.19.32 默认关闭 `reality-opts.support-x25519mlkem768`，并删除混合密钥分享；Xray 676eaf6 锁定的 REALITY 4bb46b2afd8b 会拒绝缺少该分享的握手。
- 独立实例中复制同一节点，仅切换此字段：两个节点关闭时各 0/3，通过时各 3/3。随后固定物理 WAN 出站、明确 DNS 与服务器 IPv4，再做一次对照，结论仍是各 0/3 → 3/3。
- UUID、公钥、short ID、SNI、目标站、Vision flow 和服务端端口均没有为此测试更换。不是“换一个伪装站就能解决”的问题。

一手来源：[mihomo v1.19.32 配置字段](https://raw.githubusercontent.com/MetaCubeX/mihomo/v1.19.32/adapter/outbound/reality.go)、[客户端握手处理](https://raw.githubusercontent.com/MetaCubeX/mihomo/v1.19.32/component/tls/reality.go)、[Xray 676eaf6 依赖](https://raw.githubusercontent.com/XTLS/Xray-core/676eaf6/go.mod)、[对应服务端握手检查](https://raw.githubusercontent.com/XTLS/REALITY/4bb46b2afd8b/tls.go)。

## 2. 最终有效的短窗口实测

独立 mihomo 实例在路由器上运行，不接管 TUN，不修改正式代理组。实际连接显式绑定无线 WAN，节点入口使用已核实的服务器 IPv4，SNI 和认证参数保持原值。辅助 DNS 只在独立 loopback 端口监听，使用明确的上游，不替换系统 DNS。IPv4 为本轮测试范围；探测继承正式配置的 unified-delay 和 tcp-concurrent。

每种协议进行 10 次 HTTPS 小请求探测（5 秒预算），并两次下载同一 HTTPS 端点的 262144 字节；下载预算为 15 秒。下表是有限样本，不是包丢失率、长连接成功率或峰值带宽。

| 协议 | HTTPS 探测成功 | 延迟中位数 ms | 延迟范围 ms | 256 KiB 下载成功 | 两次下载用时 s |
| --- | --- | ---: | ---: | --- | --- |
| VLESS TCP + REALITY / Vision | 10/10 | 210.5 | 189–750 | 2/2 | 1.75 / 5.06 |
| VLESS XHTTP + REALITY | 10/10 | 214 | 196–244 | 2/2 | 4.66 / 2.04 |
| VLESS WebSocket + TLS | 10/10 | 226 | 201–685 | 2/2 | 5.38 / 4.97 |
| Trojan + TLS | 10/10 | 203.5 | 198–248 | 2/2 | 13.86 / 2.68 |
| Hysteria 2 / QUIC | 10/10 | 231 | 212–482 | 2/2 | 1.92 / 0.94 |
| WAN 直连对照 | 10/10 | 196 | 172–1855 | 2/2 | 1.94 / 1.47 |

下载数据包含新连接和 TLS 建立耗时，样本较小，且按轮顺序测试；不能将此表解释为协议长期速度排行。Trojan 的一次 13.86 秒下载是有效观测，说明恢复握手后仍不能宣称全链路“已最优”。DIRECT 小请求也出现长尾，后续需要控制测试目标、时间段、链路拥塞等共同因素。

下载时 curl 的 verify=0 是最终 HTTPS 目标证书校验通过，不代表 Hysteria 外层自签证书已经通过公共 CA 验证。

## 3. 每种协议的专业判断

| 协议 | 当前正确之处 | 仍需改进或验证 | 建议定位 |
| --- | --- | --- | --- |
| TCP REALITY / Vision | Vision flow、Chrome 指纹、XUDP 与服务端匹配 | 必须修复混合密钥交换；需持续测重连和长连接 | 修复后可作为主力候选，不能仅凭协议名断言最快 |
| XHTTP REALITY | mihomo 1.19.32 支持 XHTTP，path/host/mode 字段正确；没有错误叠加 Vision | 同一个混合握手缺陷；HTTP 传输模式和版本组合增加兼容边界 | 有明确传输需求时选用；本次短样本平稳不等于长期最优 |
| VLESS WebSocket / TLS | 443/nginx、路径、TLS/SNI 参数对齐，实际能出网 | HTTP 升级/帧封装与反代层有成本；需测长时间传输 | 广泛兼容的备用路线；无需为追求“新”盲目替换 |
| Trojan / TLS | TLS/SNI 和密码方式与服务端一致，探测可用 | 曾记录连接超时，本轮也有慢下载；不能以一个低延迟样本证明稳定 | 适合简单可靠的主力/备用候选，需结合持续监测 |
| Hysteria 2 | QUIC、三个端口跳跃配置可用；客户端未硬填不实带宽 | UDP 可达性/限速、端口切换、长连接尚需长测；外层跳过证书验证不是理想身份认证 | UDP 路径良好时的候选；不是所有弱网都必然最快 |

Hysteria 服务端当前 1 Gbps/500 Mbps 是硬编码上限，不是实测线路容量；服务端上限也不等于客户端已启用相同速率的 Brutal。客户端没有 up/down 时应依对应内核默认拥塞控制判断，不能错误地把所有抖动归咎于“填了 1 Gbps”。后续应按测量结果配置容量，或保留自动拥塞控制。外层信任改进应走有效证书或证书固定，并验证客户端兼容，不能靠继续关闭校验“优化”。

本轮路由器资源快照为 load 0.16/0.20/0.14、可用内存约 163 MiB；WAN Wi-Fi 信号 -49 dBm，PHY 协商速率较高。这只是瞬时读数，未显示持续满载，不能据此排除所有硬件或无线抖动。

## 4. 已完成的本地代码修复

1. 普通、XHTTP、链式本机 REALITY 的 Clash/mihomo 导出均显式带混合握手选项。
2. 新默认字段进入 reality 配置与设备内容哈希，旧状态加载后可触发订阅重新拉取，防止服务端代码更新却继续使用旧订阅。
3. 旧服务端兼容场景可显式配置 `reality.support_x25519mlkem768=false`；这不是“所有历史版本兼容”的实机承诺。
4. 已有零延迟失败历史的节点显示“探测失败”，不再冒充尚未测速；未知原因的失败不再都称为超时。
5. 修正服务端 minClientVer 的不准确注释：当前内核留空不会自动要求达到服务端产品版本，0.0.0 也不能绕过混合 key_share 校验。

现场审计未修改线上服务器、正式订阅、正式路由器配置或当前选组，新选项在隔离实例中验证。本次代码修复随面板 v2.13.7 / 路由器客户端 v1.4.57 分发；线上部署由操作者执行。

## 5. 后续优先级

- P0：部署兼容性修复版本，并验收正式设备重新拉取后的两种 REALITY 可用性。
- P1：将真实 Xray↔mihomo 五协议端到端握手列为发行门禁，记录精确内核版本。服务器默认跟随 latest，而客户端固定版本，不能再仅依配置解析或服务器自测判断兼容。
- P1：另行修复此前发现的 curl 35 证书错误误分类与 perf 模块覆盖 agent 日志标签；本轮未将这项独立修复混入。
- P2：在不同时间段做至少较长持续请求、重连、长连接、受控大文件和 UDP 测试，再决定主备顺序、超时及自动选择容忍度。
- P2：改善 Hysteria 外层证书信任和带宽设置；先测量，不预设 MTU、缓冲、带宽越大越好。

## 6. 测试方法中的排除项

早期未绑定物理接口的临时进程可能再次经过现有 TUN，所以其 DIRECT 不作为纯 WAN 对照，性能数值不纳入最终表。第一次强制接口但仍使用系统 loopback DNS 的测试中，正常 Trojan 对照也失败；该批已作废。最终表仅使用 `*-wan-direct.json`，并保留错误批次便于复核。

测试脚本没有使用系统默认不存在的 nohup；测试进程由独立 SSH 子会话管理。每批结束后停止临时内核并删除包含凭据的临时配置。

官方字段与版本取舍详见 [上游一手资料核对](PROTOCOL-UPSTREAM-RESEARCH-2026-11-15.md)。原始无凭据测试数据保存在工作区 outputs/ZeroProxy-Protocol-Audit-2026-11-15/。
