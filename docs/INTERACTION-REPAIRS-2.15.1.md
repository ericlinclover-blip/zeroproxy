# v2.15.1：补齐网络变更确认保护

日期：2026-11-16。面板 v2.15.1；路由器客户端保持 v1.4.59。本次只需升级面板。

## 已补齐的范围

在 v2.15.0 高级设置和域名保护的基础上，网页以下操作接入同一套持久化限时确认：

| 类型 | 覆盖操作 |
|---|---|
| 节点 | 普通节点、链式节点启停；显式 enabled 与旧 toggle 路由 |
| Hysteria | 端口跳跃开关与端口区间恢复 |
| 链式入口 | 添加、启停、改名、默认出口、内层传输切换、更新配对码、删除 |
| 链式落地 | 生成/轮换凭据、修改端口、内层 QUIC 开关、关闭落地端 |
| WireGuard / AmneziaWG | 启停、模式、监听端口、网段、MTU、DNS、IPv6、混淆参数及重新生成 |
| WireGuard 客户端 | 添加、修改、启停、有效期、兼容模式、删除、轮换密钥 |

应用成功后开始 90 秒倒计时。用户测试后在顶部点击“保留变更”，或点击“立即回滚”；超时和进程重启由服务端恢复旧配置并重新应用验证。浏览器关闭不会取消后台保护。失败回滚与外部配置漂移仍按 v2.15.0 的机制单独报告。

删除和轮换同样是临时变更：未确认时会恢复旧条目、密钥和授权。界面在相关操作前后解释此行为。下载的新客户端配置或复制的新配对码可能在回滚后失效，需使用最终保留的配置；不会撤回已经发出的副本。已有连接是否立即中断取决于协议及内核生命周期。

## 事务和兼容处理

- 网页通过 `X-ZP-Confirm: 90` 显式请求保护，并通过 `X-ZP-Revision` 校验配置版本。旧 API 不带确认头时保持原行为。高级设置/域名原有请求体协议保持兼容。
- 仅固定的网络变更路由支持新协议；读取、测速、配置下载及一次性分享链接不会误创建网络保护快照。
- 认证后保存操作前的相关配置字段；链路探测完成后在提交位置重新认证和校验版本，防止等待探测时覆盖并发修改。
- WireGuard 的候选状态和保护记录同一次写盘，之后才在配置锁外同步接口。异常会标记待恢复，不留下没有期限的半提交。
- 回滚先取得应用锁和 WireGuard 事务锁，再恢复旧字段；事务忙时手动操作返回 409，后台看门稍后重试，不先覆盖正在同步的状态。
- 外部配置漂移造成的回滚拒绝会保留原校验目标，重复点击仍不覆盖外部修改；回滚失败使用独立失败审计事件和中文名称。
- 原有配对码更新失败补偿继续执行。强制添加未通过探测的链路保留失败证据和警告，应用成功不再被探针失败误判；只有用户确认后才保留，界面不会称其已验证出网。
- 等待确认期间仍允许登录、读取状态和导出备份。配置写入互斥；WireGuard 到期标记任务在短暂保护窗口内延后，完成确认或回滚后继续处理，生成配置仍按实际到期时间过滤 peer。

## 本地验收

新增 `backend/tests/test_guarded_network_mutations.py`，31 项本地回归：覆盖各类变更/恢复、同步与异步、版本冲突、重复提交、旧 API、探测并发、原有失败补偿、WireGuard 事务锁、异常恢复、到期任务恢复及强制添加的警告语义。

新增 `scripts/guarded_network_ui_check.cjs`，以真实浏览器验证节点保留、链路撤销、WireGuard 启用/密钥轮换撤销/MTU 超时恢复以及 820/390/320px 布局。原主面板浏览器回归增加实际点击确认步骤，不跳过保护协议。

完整命令与结果记录在 [VALIDATION.md](VALIDATION.md)。本次不改路由器运行时，沿用 v1.4.59；升级模拟、后端、浏览器和发布摘要在本地隔离环境验证。

## 线上由操作者验收

优先测试有独立管理入口的节点开关、链路默认出口和 WireGuard MTU：分别验证确认保留、主动撤销和超时恢复。轮换/删除授权时，核对保留后旧授权是否撤销、超时后旧授权是否恢复。

真实协议握手、LAN 接管、双服务器链路、已有会话撤销和长期稳定性没有用本地替身测试冒充通过；按既定安排由操作者在线上验收。本次补齐上一轮明确列出的节点、链路和 WireGuard 代码覆盖缺口。
