# v2.13.2 / 路由器 v1.4.52 · 连接场域配套界面

## 本次补齐的范围

之前 v2.13.0 的视觉升级只覆盖服务器面板；路由器本机 `/cgi-bin/zeroproxy` 和 LuCI 内嵌页仍在使用独立的蓝色卡片样式。本次直接升级它们共同使用的 `client/luci/index.html`、`app.js` 和 `perf.js`，没有新增前端框架、外部字体、图片或网络资源。

- 骨白底色、墨黑连接画布、酸柠绿路径、等宽标注与连续计数栏，与服务器面板采用同一主题。
- 网络、路线、设备、诊断、维护五个工作区；软件更新与系统日志集中到维护。当前工作区和深浅主题跨刷新保留。
- 路径表达局域网 → 路由器数据面 → 当前代理组选中路线。它是配置视图，不是所有设备的实时流量图，也不证明所有分流使用同一出口。
- 接管详情显示实际接管方式、范围、IPv6、策略、订阅来源、应用版本记录和最近读取时间。
- 手机端路径纵向重排；320/390/768/820/1024/1440px 下五个工作区均检查了页面宽度。
- 策略与节点延迟操作使用原生按钮，增加焦点样式、当前工作区与选中状态语义；输入字号照顾手机浏览器。

## 与交互有关的修正

1. 原页面把 WAN 收发合计当成下载速率，再按 15% 编出上传速率。本次移除这段推算。CGI 增加 `wan_rx`、`wan_tx`，前端按各自计数差显示收、发速率；`wan` 保留为合计计数。
2. 新 CGI 无法读取计数时返回空值；旧接口（包括仍使用现有 zpcore 的入口）缺少分方向字段时显示未知，不拿合计数冒充下载或上传。WAN 计数包含直连与代理，不等于代理专用流量。
3. `applied_rev` 来自路由器的 `applied.rev` 历史应用记录，不将它当成当前进程或出口健康证明；旧接口缺少记录时明确显示未提供。
4. REDIRECT 明确仅局域网 TCP，TPROXY 不包含路由器自身；IPv6 未接管时标明会直接出网。缺少数据面时，即使残留的覆盖字段为 full，也不显示接管就绪。
5. DHCP/邻居发现清单只显示“已发现”，不再一律显示绿色“在线”，也不将发现记录当成代理接管证明。
6. 当前代理组选中只用于描述选组；没有延迟证据时不显示“就绪”来冒充出网验证。性能模式说明采用统一组，不开放标准模式的三档策略和独立节点测速。
7. 轮询状态不重建内容未变化的订阅来源与节点按钮，保留接入草稿和操作焦点；代理组状态会定期重新读取。
8. 断线标记状态未知、禁用写操作并保留上次信息，恢复后读取实际状态；不会自动重放开关或移除操作。总开关提交后等待状态回报，不将“请求已收到”当成“已应用”。
9. 性能模式继续使用真实 WAN 计数驱动现有 SVG 表盘；“100 Mbps”明确为表盘量程，不宣称实际带宽上限。操作文案改为“启用性能模式 / 切回标准模式”。

## 怎样让路由器看到新界面

服务器和路由器保存的是两份文件。仅升级服务器面板，不会自动替换路由器本机页面。

1. 先将服务器面板升级到 **v2.13.2**，使它开始提供新界面文件和 **v1.4.52** 客户端安装脚本。
2. 在路由器旧版页面的“节点路线 → 客户端软件维护与升级”点击 **更新客户端**；新版对应“维护 → 更新客户端”。
3. 等待更新完成后重新打开 LuCI 的“服务 → ZeroProxy”，或使用原有授权管理地址。

也可以在路由器 SSH 中执行现有命令：

```sh
zeroproxy update
```

客户端版本由 `router_client.SCRIPT_VERSION` 发布，更新会重新分发 HTML、JS 与 CGI。zpcore 仍为 v1.3.2，本轮未改 Go 二进制；不提供新遥测字段的入口会如实显示字段缺失。
