# v2.13.6 / 路由器客户端 v1.4.56

本轮修复路由器「当前代理组路线」持续显示「代理组状态未知」，并修正同一链路中的测速和选组问题。

## 根因与改动

- CGI 与 zpcore 的 proxies 和 test-delay 接口透传 mihomo 原始 JSON，未包含前端统一要求的 `ok:true`。前端现只对这两个接口的已知结构兼容；HTTP 失败、显式 `ok:false`、无效响应仍报错。其他写操作继续要求成功标识。
- 旧代码在同一次 `find()` 中匹配「节点选择」和 GLOBAL。真实接口将 GLOBAL 放在前面，导致规则模式可能读取或修改错误组。现按当前分流模式明确优先级，并将组名纳入渲染签名。
- CLI 将路径中的空格替换为 `+`，但 URL 路径不会将它解码为空格。现使用已有的 BusyBox awk 按字节生成百分号编码，不依赖部分固件缺少的额外工具，覆盖中文、emoji 和特殊字符。
- 删除指定组切换失败后尝试修改 GLOBAL 的行为，避免错误操作其他组并报告成功；测速零值使用失败颜色。
- 浏览器模拟接口改用与真实 CGI/zpcore 相同的原始响应，新增实际前端请求和渲染行为、失败恢复、组优先级、路径编码与禁止错误回退的测试。

## 升级顺序

先升级服务器面板到 **v2.13.6**，再在路由器维护页更新客户端到 **v1.4.56**，完成后重新加载 LuCI 页面。服务器与路由器各自保存代码，仅刷新浏览器不会更新路由器文件。

zpcore 仍为 v1.3.2，本次不修改 Go 二进制，也不需要更换 mihomo 内核。

## 现场与边界

GL-MT3000 / OpenWrt 24.10.4 上已验证修复前原始节点响应正常、页面误报失败；就地补丁后恢复「♻️ 自动选择」与候选节点列表，页面 Trojan 测速返回 214 ms。未切换原有路线、未重启内核，未改变远程服务器配置。

就地补丁保留 v1.4.55 标识，本次发行通过 v1.4.56 使正常升级渠道也能安装修复。两个 Reality 节点的探测失败属于独立问题，不由此次界面修复解决。
