# v2.15.0 后续修复与本地验收

2026-11-16；面板 v2.15.0，路由器客户端 v1.4.59。

## 网络变更保护

网页的高级设置（端口、Reality SNI、Hysteria 伪装）和域名切换使用同一套持久化确认机制。服务端应用成功后开始 90 秒倒计时；用户测试连接后点击“保留变更”。不确认会自动恢复旧字段、重新生成配置并验证，浏览器关闭或断线不影响服务端计时。域名切换后在新入口完成确认。

- 应用失败立即排队回滚；进程重启发现未确认的变更也执行恢复。磁盘写入异常会继续尝试，服务验证失败明确显示回滚失败，可手动重试。
- 恢复时只处理该次操作的配置字段，保留账号、会话和设备心跳。若这些字段被服务器外部工具改写，会拒绝覆盖并显示需人工恢复。
- 等待确认/回滚期间阻止其他管理配置写入；允许登录、退出、会话交接、读取状态和设备诊断。
- 旧 API 调用不带 `require_confirmation` 时保留原行为；限时保护没有替代原有配置校验和应用失败补偿。节点、链路和 WireGuard 等其他接口继续使用原有应用/验证流程，本版本未给它们增加网页二次倒计时。
- 保护对象是配置与服务恢复，不会撤销已发放的订阅副本、证书签发记录或额外放行的防火墙端口，也不能保证网络本身及独立服务器终端可达。

本地回归覆盖确认幂等、过期拒绝确认、后台无人确认回滚、重启恢复、回滚失败重试、配置漂移保护、任务启动异常及失败步骤无详情的处理。

## 自定义分流规则分析

保存前由服务端按实际优先级分析：拦截、落地、AI、流媒体、代理、直连。识别相同目标、父子域名、IPv4/IPv6 CIDR 包含以及先匹配子范围的部分覆盖；展示前者与后者及实际作用关系。新增和删除统计使用规范化目标，不把 IP 与对应 `/32` 或 `/128` 误算作不同规则。

最多分析 2048 条，详情最多展示 200 对，冲突总数仍完整计算。预览带设置版本，保存时若其他窗口修改了分流或服务器配置，会返回 409，不覆盖新版本。

分析只覆盖自定义静态规则；不通过 DNS 推断域名和 IP 的对应关系，不推断 Geo 规则或客户端手动选组。系统基础防护仍有更高优先级。

## 设备分阶段诊断

升级路由器客户端后，设备卡片可发起一次诊断。请求通过现有设备心跳下发随机标识，不包含远程命令或可选目标。设备只执行固定本地命令 `zeroproxy doctor-json`，每个请求执行一次，下次心跳回报。

| 阶段 | 证据及边界 |
|---|---|
| 设备进程 | 本机服务运行状态；不代表实际握手 |
| 本机 DNS | 5 秒以内向本机 DNS 查询固定域名；缺少所需工具则未验证 |
| 接管计数 | 当前模式与记录一致时读取累计包计数；无流量不能证明接管失败，有计数也不证明当前 LAN 终端路径 |
| 首个 TCP 入口 | 固定读取配置中的首个 TCP 节点，限时探测；Hysteria UDP 不使用 TCP 探测冒充协议验证 |
| 本机代理响应 | HTTPS 目标成功时记录有响应证据；不确认出口公网地址或具体节点身份 |
| 固定 HTTPS 目标 | 通过本机显式 HTTP 代理访问 gstatic generate_204，正常验证 TLS，8 秒截止且只接受 204；性能模式不做这个探针，显示未验证 |

诊断请求 120 秒到期，错配、超时和重复回报不刷新结果时间；完成结果超过 5 分钟标为过期。回报使用字段和状态白名单，不保存命令输出、浏览历史、域名、原始异常或凭据。诊断导出只附阶段状态和时间，不附设备名称/IP/秘密。

## 本地与线上验收边界

本轮只在本地隔离环境运行 API、真实浏览器、Shell 替身、路由器安装和升级演练；未连接或升级线上服务器与路由器。Xray/Hysteria 真实二进制缺失的测试继续明确跳过。

线上由操作者验收：

1. 先升级面板到 v2.15.0，再更新路由器到 v1.4.59，等待新心跳显示客户端版本。
2. 修改一次高级设置，测试连接后点“保留变更”；再次修改后不确认，观察恢复旧值及连接。
3. 更换域名时在新入口 90 秒内确认；需要验证超时恢复时，保留旧入口与服务器终端。
4. 在设备卡片发起分阶段诊断，核对实际设备进程、DNS、计数及固定目标结果。另用 LAN 终端验证接管与实际协议握手。
5. 验证标准/性能模式、真实双服务器链路、已有会话撤销及长期吞吐。这些不能由本地替身测试证明。

完整结果见 [VALIDATION.md](VALIDATION.md)，新增回归见 `backend/tests/test_completion_repairs.py` 和 `scripts/completion_ui_check.cjs`。
