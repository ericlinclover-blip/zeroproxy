# v2.13.4 / 路由器 v1.4.54：旧 LuCI 外框兼容

## 现场证据

通过只读检查用户当前已打开的 Chrome 路由器页面确认：

- 内页显示客户端 v1.4.53，已识别嵌入模式。
- 外层仍执行旧承载代码：`src=/cgi-bin/zeroproxy`，内联 `height:78vh`，不是新版承载页。
- 当时外框高度约 802px，内页实际高度约 1307px，内页根节点没有主题桥接写入的行内变量。
- 宿主通过固定视口高度的 `.main-right` 区域滚动。首次网络页仍显示静态的独立页标题。

这些证据说明“内页已升级”不能证明“外层已加载新脚本”。没有修改真实路由器设置，也没有在现场注入补丁。

## 修复

1. 把同源主题与尺寸适配的生命周期移入内页 `app.js`。已加载或缓存的旧 LuCI 承载页无需先替换，就能被新内页自动适配。
2. 只调整所属 iframe 的高度、最小/最大高度和宽度；高度使用行内重要声明，避免宿主固定高度规则再次覆盖。内容仍由宿主滚动区域滚动。
3. iframe 随内容增高和缩回；内页卸载时清理宿主观察器与监听，恢复缓存页面时重新建立适配。
4. 默认工作区也走初始化流程，首次进入即显示“网络接管”，不依赖之前是否保存过工作区。
5. 桌面连接图收紧为三段路径，详情采用双列，减少对接管开关、分流与统计的挤占。独立页主题保留。
6. 新 LuCI 承载页只负责创建 iframe；安装包内置兜底与离线缓存同步更新。

## 验证

浏览器夹具增加旧 `78vh` 承载脚本，以及与现场一致的固定视口、外层滚动区域。额外施加重要高度及最大高度限制，检查内页仍能自动修正、底部可达、切换后缩回，并在旧外框下同步主题。也保留独立页、现代外框、六种宽度和五工作区检查。完整结果见 [VALIDATION.md](VALIDATION.md)。

先升级服务器到 v2.13.4，再更新路由器客户端到 v1.4.54，重新加载内页获取新代码即可。此次兼容修复不要求 LuCI 外层必须先清缓存、加载新版承载脚本。
